# Contributing to UTool

Thank you for your interest in contributing to UTool! This repository contains documentation and resources for various Unity tools and packages.

## How to Contribute

### Reporting Issues

- Use the issue templates provided in `.github/ISSUE_TEMPLATE/`
- Clearly describe the problem or suggestion
- Include Unity version and relevant environment details
- Add screenshots or examples when helpful

### Documentation Improvements

We welcome improvements to documentation:

- **Bilingual Support**: All documentation should have both English (`README.md`) and Chinese (`README-CN.md`) versions
- **Consistency**: Follow the existing structure and formatting conventions
- **Clarity**: Keep explanations concise and practical
- **Examples**: Include code examples and use cases where appropriate

### Style Guidelines

#### Documentation Format

- Use shields/badges for version and status information
- Include navigation links: `English | [简体中文](./README-CN.md) | [Return to Main](../README.md)`
- Structure sections consistently: Overview, Features, Quick Start, Resources
- Keep content focused and remove unnecessary filler text

#### Markdown Conventions

- Use `##` for main sections, `###` for subsections
- Format code blocks with language identifiers: ```csharp, ```bash, etc.
- Use relative paths for internal links
- Add horizontal rules (`---`) between major sections

### Pull Request Process

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/your-feature-name`
3. Make your changes following the style guidelines
4. Test documentation rendering if applicable
5. Commit with clear, descriptive messages
6. Submit a pull request using the provided template
7. Respond to any feedback from reviewers

### Component-Specific Guidelines

When contributing to specific tool documentation:

- **Cinemachine**: Focus on camera systems and virtual camera setup
- **Game Creator**: Emphasize visual scripting and no-code workflows
- **MlskyUI**: Cover UI themes and component usage
- **UniTask**: Include async/await patterns and performance tips
- **RadialMenu**: Document configuration and customization options
- **Synty**: Cover low-poly assets, optimization, and best practices

## Questions?

If you have questions about contributing, feel free to open an issue for discussion.

Thank you for helping improve UTool!
